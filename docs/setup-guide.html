MemPalace MCP: Complete Installation Guide

Author: Vasily S. Levin Revised: 2026-06-30 Windows 11 WSL2 Docker Tailscale Funnel

Environments Explained

This guide uses two environments. Every code block is labeled so you always know where to run it.

Black PowerShell icon (Run as Administrator)Windows environment. Right-click the black PowerShell icon in the Start menu and select Run as Administrator.
WSL (Ubuntu) — Linux shellLinux environment running inside Windows. To enter: open black PowerShell, type wsl and press Enter. Your prompt changes from PS C:\> to user@machine:~$. To leave WSL and return to PowerShell, type exit.
sudo password: The first time you run a sudo command in a WSL session, Linux asks for your UNIX password. This is the password you set when Ubuntu opened for the first time after WSL installed (step 1c). It is not your Windows password. After entering it once, subsequent sudo commands in the same terminal window do not prompt again for approximately 15 minutes.
Prompt reference:
PowerShell: PS C:\Users\you>
WSL (Ubuntu): you@machinename:~$

Overview and Architecture

MemPalace runs as a Docker container inside WSL2 on Windows 11. Tailscale Funnel exposes the container port to the public internet over HTTPS so Perplexity can reach it as a custom MCP connector. The data directory is a bind mount so palace contents survive container rebuilds.

ComponentRoleConfig
Docker containerRuns MemPalace MCP servermempalace-mcp on local port 8080
Bind mountPersists palace data outside container/home/user/mempalace-data:/root/.mempalace
Tailscale FunnelProxies public HTTPS (443) to local 8080https://<hostname>.<tailnet-id>.ts.net/mcp
WSL cronSnapshots palace every 6 hours0 */6 * * * backup-mempalace.sh
Perplexity MCPConsumes the MCP endpointCustom connector URL at /mcp
Path note: Live data is at /home/user/mempalace-data (WSL native filesystem). SQLite and ChromaDB need POSIX file locking, which Windows 9P mounts (/mnt/c, /mnt/d) do not implement correctly. Never place palace data on a mounted Windows path.
Port note: Tailscale Funnel listens on public port 443 (standard HTTPS) and forwards to your local container on port 8080. Both numbers are correct and refer to opposite sides of the proxy.
1
Windows Prerequisites
1a. Install and Clean Up PowerShell

Windows ships with two PowerShell versions. The old one has a blue icon and is named Windows PowerShell. The new one has a black icon and is simply named PowerShell. This guide requires the black icon version throughout. Step 1a installs it, removes old shortcuts, and removes any outdated standalone copy.

Open the blue Windows PowerShell as Administrator for this one step only. After step 1a completes, close it and use only the black PowerShell icon for everything that follows.

Blue Windows PowerShell as Administrator (this step only)
# Install the new black PowerShell
winget install --id Microsoft.PowerShell --source winget --accept-package-agreements --accept-source-agreements

# Remove old Windows PowerShell shortcuts from Start menu
$oldPSPath = "$env:APPDATA\Microsoft\Windows\Start Menu\Programs\Windows PowerShell"
if (Test-Path $oldPSPath) {
    Get-ChildItem $oldPSPath | Remove-Item -Force
    Write-Host "Old Windows PowerShell shortcuts removed."
} else {
    Write-Host "No old shortcuts found."
}

# Remove any outdated standalone PowerShell version installed via MSI
$installed = winget list --name "PowerShell" 2>$null
$old = $installed | Select-String "PowerShell" | Where-Object { $_ -notmatch "^\s*Name" -and $_ -notmatch "7\.[6-9]|[89]\." }
if ($old) {
    $ver = (($old -split "\s+") | Where-Object { $_ -match "^\d" } | Select-Object -First 1)
    winget uninstall --name "PowerShell" --version $ver
    Write-Host "Outdated PowerShell version removed."
} else {
    Write-Host "No outdated standalone PowerShell version found."
}

Close the blue PowerShell window. From this point forward, right-click the black PowerShell icon in the Start menu and select Run as Administrator for every step labeled "PowerShell as Administrator."

Verify: Open the black PowerShell as Administrator and run $PSVersionTable.PSVersion. The Major version should be 7 or higher.
1b. Verify Virtualization
Black PowerShell icon (Run as Administrator)
PowerShell as Administrator
Get-ComputerInfo -Property HyperVisorPresent

Must return True. If False, enable Intel VT-x or AMD-V in BIOS before continuing.

1c. Install WSL2
Black PowerShell icon (Run as Administrator)
PowerShell as Administrator
wsl --install

Reboot after this command. Some machines prompt. Some do not. Reboot regardless.

After reboot, Ubuntu normally opens automatically and asks for a UNIX username and password. If it does not open automatically, find Ubuntu in the Start menu and launch it manually. Set and record the username and password. This password is what Linux asks for whenever you run sudo in WSL.

If Ubuntu opens but does not prompt for a password at all, set one manually:

WSL (Ubuntu)
passwd
The wsl command to enter Linux is normally available after this reboot. If it is not recognized immediately, wait 30 seconds and try again, or reopen PowerShell.

2
WSL2 Stability Fix (.wslconfig)

WSL2 aggressively reclaims RAM during idle periods and can suspend container processes without a visible crash. Cap memory before starting Docker. The .wslconfig location follows your .cfg disk layout: a file symlink at the hardcoded path WSL2 reads, with the real file under .cfg\wsl\. WSL2 follows the symlink transparently. File symlinks require PowerShell to be run as Administrator or Developer Mode enabled in Windows Settings.

Black PowerShell icon (Run as Administrator) for all steps in this phase

2.1 Dual-drive (C: OS + D: data)

Real file: D:\.cfg\wsl\.wslconfig. Symlink: C:\Users\<username>\.wslconfig points to it.

PowerShell as Administrator
New-Item -ItemType Directory -Path "D:\.cfg\wsl" -Force

echo "[wsl2]`nmemory=8GB`nswap=0" | Out-File -FilePath "D:\.cfg\wsl\.wslconfig" -Encoding utf8

$src = "C:\Users\$env:USERNAME\.wslconfig"
if (Test-Path $src) { Remove-Item $src -Force }
New-Item -ItemType SymbolicLink -Path $src -Target "D:\.cfg\wsl\.wslconfig"

Get-Item -Force $src | Select-Object FullName, LinkType, Target
# Expected: LinkType = SymbolicLink, Target = D:\.cfg\wsl\.wslconfig

2.2 Single-drive (C: only)

Real file: C:\Users\<username>\.cfg\wsl\.wslconfig. Symlink: C:\Users\<username>\.wslconfig points to it.

PowerShell as Administrator
New-Item -ItemType Directory -Path "$env:USERPROFILE\.cfg\wsl" -Force

echo "[wsl2]`nmemory=8GB`nswap=0" | Out-File -FilePath "$env:USERPROFILE\.cfg\wsl\.wslconfig" -Encoding utf8

$src = "C:\Users\$env:USERNAME\.wslconfig"
if (Test-Path $src) { Remove-Item $src -Force }
New-Item -ItemType SymbolicLink -Path $src -Target "$env:USERPROFILE\.cfg\wsl\.wslconfig"

Get-Item -Force $src | Select-Object FullName, LinkType, Target
# Expected: LinkType = SymbolicLink, Target = C:\Users\<username>\.cfg\wsl\.wslconfig

2.3 Apply (either setup)

PowerShell
wsl --shutdown
# Wait five seconds. Docker Desktop restarts automatically.

6
Dockerfile and compose.yml
WSL (Ubuntu)

6.1 Dockerfile

WSL (Ubuntu)
cat > ~/mempalace-docker/Dockerfile << 'EOF'
FROM python:3.11-slim
RUN pip install mempalace mcp-proxy
WORKDIR /root
CMD ["mcp-proxy", "--host", "0.0.0.0", "--port", "8080", "--stateless", "--allow-origin=*", "--", "mempalace-mcp", "--transport", "stdio"]
EOF

--stateless makes mcp-proxy accept connections without a pre-existing session ID, which SSE clients including Perplexity require. --allow-origin=* permits cross-origin connections from Perplexity.

6.2 compose.yml

WSL (Ubuntu)
cat > ~/mempalace-docker/compose.yml << 'EOF'
services:
  mempalace-mcp:
    build: .
    container_name: mempalace-mcp
    restart: always
    ports:
      - "8080:8080"
    volumes:
      - /home/user/mempalace-data:/root/.mempalace
EOF

restart: always is required. The value unless-stopped causes the container to silently go offline when Docker Desktop restarts in the background. Always use always.

Start and Verify
WSL (Ubuntu)

7.1 Check Port Availability

WSL (Ubuntu)
ss -tlnp | grep 8080

No output means the port is free. If something is bound, change the host port in compose.yml.

7.2 Build and Start

WSL (Ubuntu)
docker compose -f ~/mempalace-docker/compose.yml up -d --build

7.3 Verify Restart Policy

WSL (Ubuntu)
docker inspect mempalace-mcp --format '{{.HostConfig.RestartPolicy.Name}}'
# Must return: always
# If it returns unless-stopped:
docker compose -f ~/mempalace-docker/compose.yml up -d --force-recreate

7.4 Check Logs and Mount

WSL (Ubuntu)
docker logs mempalace-mcp --tail 30
# Expect: Uvicorn running on http://0.0.0.0:8080 + Application startup complete

docker inspect mempalace-mcp --format '{{ range .Mounts }}{{ .Source }} -> {{ .Destination }}{{ println }}{{ end }}'
docker exec mempalace-mcp sh -c 'ls /root/.mempalace'
# Expected: locks  palace  wal

Tailscale Funnel

8.1 Install Tailscale

Black PowerShell icon (Run as Administrator)
PowerShell as Administrator
winget install Tailscale.Tailscale

Open Tailscale and sign in to the tailnet. Then verify from WSL:

WSL (Ubuntu)
WSL (Ubuntu)
tailscale ip -4
tailscale status
# Note the MagicDNS hostname: <machine>.<tailnet-id>.ts.net

8.2 Enable Funnel in Admin Console (mandatory)

Go to login.tailscale.com/admin/machines, find this machine, open the three-dot menu, select Edit route settings, enable Funnel, save.

8.3 Set Operator Permission (run once)

WSL (Ubuntu)
WSL (Ubuntu)
sudo tailscale set --operator=$USER

This allows future tailscale serve and tailscale funnel commands to run without sudo.

8.4 Reset, Configure Serve, and Enable Funnel

WSL (Ubuntu)
WSL (Ubuntu)
sudo tailscale serve reset
tailscale serve status
# Confirm output: No serve config

sudo tailscale serve --bg 8080
sudo tailscale funnel --bg 8080
tailscale serve status

Expected output:

Expected
https://<machine>.<tailnet-id>.ts.net (Funnel on)
|-- / proxy http://127.0.0.1:8080

8.5 Test the Endpoint

WSL (Ubuntu)
WSL (Ubuntu)
curl -s -H "Accept: text/event-stream" https://<machine>.<tailnet-id>.ts.net/mcp

SSE ping lines confirm both Funnel routing and the container are working. Without the Accept: text/event-stream header the server returns HTTP 406, which is expected and not an error.

9
Backup (WSL cron)

Live palace: /home/user/mempalace-data (WSL). Snapshot destination depends on drive layout:

SetupWindows targetWSL path
Dual-driveD:\env\mempalace\backups/mnt/d/env/mempalace/backups
Single-driveC:\env\mempalace\backups/mnt/c/env/mempalace/backups
WSL (Ubuntu)

9.1 Write WSL Backup Script

WSL (Ubuntu)
cat > ~/backup-mempalace.sh << 'EOF'
#!/bin/bash
if [ -d /mnt/d/env ]; then
    TARGET=/mnt/d/env/mempalace/backups
else
    TARGET=/mnt/c/env/mempalace/backups
fi
mkdir -p "$TARGET"
TIMESTAMP=$(date +%Y%m%d_%H%M%S)
cp -r /home/user/mempalace-data "$TARGET/mempalace-data-$TIMESTAMP"
ls -dt "$TARGET/mempalace-data-"* | tail -n +8 | xargs rm -rf
echo "[ok] MemPalace snapshot $TIMESTAMP saved to $TARGET"
EOF
chmod +x ~/backup-mempalace.sh

Grant passwordless sudo so cron can run it non-interactively, then test:

WSL (Ubuntu)
echo "$USER ALL=(ALL) NOPASSWD: /bin/bash /home/$USER/backup-mempalace.sh" | sudo tee /etc/sudoers.d/mempalace-backup

bash ~/backup-mempalace.sh
ls /mnt/d/env/mempalace/backups/ 2>/dev/null || ls /mnt/c/env/mempalace/backups/ 2>/dev/null

9.2 Set Up WSL Cron (every 6 hours)

WSL (Ubuntu)
(crontab -l 2>/dev/null; echo "0 */6 * * * /bin/bash /home/user/backup-mempalace.sh") | crontab -

crontab -l | grep mempalace
10
Connect to Perplexity

Add MemPalace as a custom connector in Perplexity. Follow these steps in order:

  1. Open Perplexity and go to Connectors.
  2. Click Add custom connector.
  3. Fill in the fields as follows:
FieldValue
IconAny image under 128 KB (optional)
NameShort and easy to recognize, e.g. mem
DescriptionMemory Palace
MCP Server URLhttps://<machine>.<tailnet-id>.ts.net/mcp
  1. Click Advanced and set the following:
Advanced fieldValue
AuthenticationNone
TransportStreamable HTTP
Network AccessPublic
  1. Check the box: I understand custom connectors can introduce risks.
  2. A disclaimer appears: "Perplexity can't verify this app or guarantee answer quality, so only use connectors from sources you trust." Click to confirm.
  3. Click Add in the bottom right corner.
  4. Confirm the connector shows as connected.
If Perplexity connects but MCP tools are never called, verify you are using Perplexity's default model. Claude running inside Perplexity does not inherit custom connectors.

Restore Data from Backup
Skip on a fresh install. Follow only when migrating an existing palace to a new machine.
WSL (Ubuntu)

11.1 Stop Container

WSL (Ubuntu)
docker compose -f ~/mempalace-docker/compose.yml down

11.2 Copy Latest Snapshot

WSL (Ubuntu)
LATEST=$(ls -dt /mnt/d/env/mempalace/backups/mempalace-data-* 2>/dev/null | head -1)
# Single-drive: replace /mnt/d with /mnt/c above
cp -r "$LATEST/." /home/user/mempalace-data/

11.3 Restart and Reconnect

WSL (Ubuntu)
docker compose -f ~/mempalace-docker/compose.yml up -d
docker logs mempalace-mcp --tail 20

After the container is running, call mempalace_reconnect via your MCP client to rebuild the HNSW vector index from the restored SQLite database.

Optional: Caddy Auth Layer (Bearer Token Enforcement) Optional ▼

By default, port 8080 is exposed through Tailscale Funnel with no token check. Caddy adds a bearer-token enforcement layer so requests without the correct Authorization: Bearer header receive a 401 before reaching mcp-proxy.

When to add this: if you share your Tailscale node with others or want an extra layer of access control beyond Tailscale's own auth.
WSL (Ubuntu) for all steps in this section

Generate a Bearer Token

WSL (Ubuntu)
python3 -c "import secrets; print(secrets.token_urlsafe(32))"

Save the output as your MCP_TOKEN. Never commit it to version control.

Write .env

WSL (Ubuntu)
cat > ~/mempalace-docker/.env << 'EOF'
MCP_TOKEN=YOUR_TOKEN_HERE
EOF
chmod 600 ~/mempalace-docker/.env

Write Caddyfile

WSL (Ubuntu)
cat > ~/mempalace-docker/Caddyfile << 'EOF'
:8081 {
    @unauth {
        not header Authorization "Bearer {$MCP_TOKEN}"
    }
    respond @unauth 401
    reverse_proxy mempalace-mcp:8080
}
EOF

Update compose.yml to add Caddy service

WSL (Ubuntu)
cat > ~/mempalace-docker/compose.yml << 'EOF'
services:
  mempalace-mcp:
    build: .
    container_name: mempalace-mcp
    restart: always
    ports:
      - "127.0.0.1:8080:8080"
    volumes:
      - /home/user/mempalace-data:/root/.mempalace

  caddy:
    image: caddy:2-alpine
    container_name: mempalace-caddy
    restart: always
    ports:
      - "8081:8081"
    env_file:
      - .env
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
EOF

mempalace-mcp now binds to 127.0.0.1:8080 (loopback only). Caddy on 8081 becomes the public-facing port. Point Tailscale Funnel at 8081:

WSL (Ubuntu)
sudo tailscale serve reset
sudo tailscale serve --bg 8081
sudo tailscale funnel --bg 8081
